# AU05 设备协议与写入实现

这份文档记录网页端「读取键表 / 写入设备」到底发了什么，以及为什么有的动作写得进去、有的写不进去。

协议不是猜的：报文格式、TEA 密钥与自检向量来自开源项目 **halokey**（`crates/proto`）与 **olanzi** 的真机验证日志，两者都注明密钥来自 Studio 的 `kwdm.dylib` 并在 macOS / Linux 实机跑通。本仓库用 JS 重写了同一套协议，并用下面的向量做过校验。

## 1. 通道与帧

| 项 | 值 |
|---|---|
| USB VID / PID | `0xFFF1` / `0x00DD` |
| 厂商通道接口 | usage page `0xFFFC`（接收器的第 3 个接口） |
| Report ID | `0x55` |
| 明文 | 64 字节（不足补 0） |
| 线上报文 | 64 字节 = `0x55` + 密文前 63 字节 |
| 加密 | TEA / ECB / 8 字节分组 / 32 轮（不是 XTEA） |
| 回复 | 64 字节带 `0x55` 前缀，或 63 字节不带前缀（macOS IOKit） |
| 可解密长度 | 回复前 56 字节（7 个完整分组），末 7 字节是填充，不解析 |

TEA 密钥字（小端拆自 16 字节原始密钥）：

```
[0xCAA5BACA, 0xBC2A8A6D, 0xCA5A9EBA, 0x9BB88BCA]
delta = 0x9E3779B9，32 轮
```

自检向量：

```
TEA_Enc(00 00 00 00 00 00 00 00) == 38 90 c4 99 a3 60 aa ad
```

`index.html` 里的 `teaEncryptBlock` 输出与该向量逐字节一致；编码 → 解码往返也与明文一致。

## 2. 键表命令

6 个设备槽位：

| index | 控件 |
|---|---|
| 0 | 键 1 |
| 1 | 键 2 |
| 2 | 键 3 |
| 3 | 旋钮按下 |
| 4 | 旋钮右旋（顺时针） |
| 5 | 旋钮左旋（逆时针） |

读：

```
→ 01 06 50 01 <index>
← 81 06 50 11 <index> 01 <num> (<type|sign<<7> <code>) × num
```

写：

```
→ 01 06 50 04 <index> 01 <num> (<type|sign<<7> <code>) × num
← 81 06 50 14 <index> …        access 0x14 = 写确认
```

条目类型：`0x02` 键盘页（code = HID Usage ID）、`0x07` 鼠标页、`0x03` 系统/多媒体页（取值范围官方未公开，属未完整实测）。每槽最多 4 条。

网页端的写入流程：写 → 等 `0x14` 确认 → 立即读回 → 逐条比对，一致才算成功。

## 3. 网页配置怎么映射到设备

| 网页动作 | 设备条目 | 说明 |
|---|---|---|
| 键盘快捷键（≤4 个键码） | `0x02`：修饰键 `0xE0–0xE3` + 主键 usage | 例如 `⌃C` → `02 E0`、`02 06` |
| 媒体控制 | `0x03`：播放 `0xCD`、下一首 `0xB5`、上一首 `0xB6`、音量 ±`0xE9/0xEA`、静音 `0xE2` | 设备是否接受以读回为准 |
| 文本 / 打开网址 / 打开应用 / 切换场景 / AI 指令 / 插件动作 | 不下发 | 这些需要宿主执行，设备只存键码 |
| 双击 / 长按 / 按压+旋转 | 不下发 | 设备没有手势概念，只有 6 个槽位 |

所以「写入设备」的结果一定分三类：已写入（读回一致）、需 Agent（动作类型设备不支持）、失败（超时或读回不一致）。

## 4. 电量

```
→ 01 01 02 01
← 81 01 02 11 <mv lo hi> <pct lo hi> … <charging>      电压 mV，充电 0/1
```

设备还会主动广播 `0b 7b …`，其中偏移 2–3 为电压、偏移 5 为百分比。网页端两种都解析，取代了早期按报文首字节估算电量的做法。

## 5. 已知边界

- 必须选到 usage page `0xFFFC` 的厂商接口；选到标准键盘接口会提示"没有厂商通道接口"。
- Windows 要求输出报告与描述符等长，Chrome 会按 report ID 补齐；若某些固件描述符异常，`sendReport` 会直接报错。
- 写操作只影响目标槽位，失败不会改动其他槽位；但**没有实现"整表备份/恢复"**，介意的场景请先用「读取键表」把当前值抄下来。
- 设备端只有 6 个槽位，网页里 12 个输入位（含手势）是超集，超出部分由本地 Agent 承担。
